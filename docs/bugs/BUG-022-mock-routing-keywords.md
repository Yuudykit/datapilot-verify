# BUG-022：mock 路由关键词优先级不当，混合问题与门店表检查被错误处理

- 日期：2026-08-30
- 模块：LangGraph 路由 / OfflineAgent
- 级别：P2
- 状态：已修复

## 现象

- 混合问题如"净销售额的口径是什么？顺便按渠道看 7 月为什么下降"，因为
  命中"口径"关键词，只返回定义文本，分析请求被静默丢弃。
- 问"门店维表有多少行？"，`inspect_dataset` 写死读取 orders.csv，
  回答的是订单表而不是门店表。
- 维度值取不到时（例如订单的 store_id 关联不上门店维表，region 为
  NULL），答案会拼出"None是变化最大的区域"。

## 根因

`_route_after_metric` / `OfflineAgent.ask` 的关键词分支只按固定顺序匹配，
缺少"分析意图"这一优先级；`_inspect_dataset` 未按问题选择数据文件；
答案模板直接 `top.get(dimension, ...)`，默认值不覆盖值为 None 的情形。

## 修复与验证

- 路由顺序调整为：数据检查 → 口径歧义澄清 → 分析意图
  （下降/上涨/变化/比较/为什么）→ 口径问答 → 兜底；offline 同步。
- `_inspect_dataset` 按问题中"门店/维表"选择 stores.csv，答案带文件名。
- 维度显示统一为"取不到时显示未知分组"（BUG-017 已在图中先行引入，
  本次补齐 offline）。

新增图级回归：混合问题进入 run_analysis、门店维表检查返回 11 行。
验证：14 个相关测试通过。
