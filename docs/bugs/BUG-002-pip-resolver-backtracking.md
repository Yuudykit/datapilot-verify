# BUG-002：pip 依赖解析长时间回溯

## 摘要

首次执行可编辑安装后，pip 长时间占用 CPU 且没有进入下载阶段。

## 影响

阻塞工程基线验证；持续等待无法提供确定的安装结果。

## 根因

初步观察为解析回溯；打开 pip 日志和拆分安装后确认，主要瓶颈是包索引/文件服务连接超时。默认 PyPI 可间歇下载，但 Streamlit、PyArrow 等大 wheel 长时间无进度；清华源 60 秒无元数据响应，阿里源对单个 langgraph 30 秒无响应。同时初版不必要的版本上界会放大解析成本。

## 修复

- 中止无产出的下载/解析进程，并清理残留 Python 进程。
- 根据当前 Python 3.11 包生态移除不必要上界，保留最低兼容版本。
- 拆分核心依赖和 UI/Agent 扩展依赖；核心依赖已成功安装。
- 每次镜像尝试使用有限超时和重试，失败后停止，不持续轮询。
- 完整依赖安装后使用实际解析结果生成锁定清单。

## 验证

- 核心环境已验证：DuckDB 1.5.5、pandas 3.0.5、Pydantic 2.13.5、SQLGlot 30.17.0。
- 25 项测试全绿，离线 Tool demo 可运行。
- LangGraph/Streamlit/Plotly/SciPy 等扩展依赖待网络恢复后补装。

## 预防

- 应用项目使用 lock/constraints 文件保证复现。
- 库项目才优先维护宽兼容区间；本项目不是通用发布库。
